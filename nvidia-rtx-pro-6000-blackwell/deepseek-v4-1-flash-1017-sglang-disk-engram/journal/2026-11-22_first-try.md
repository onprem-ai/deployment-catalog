# 2026-11-22: bring-up on a 4x RTX PRO 6000 Server Edition host (61 GB RAM, 10 GB swap)

Result: serving, correct output, host RAM well under the limit.

## Why this stack
- The BRRR profile needs io_uring (Docker's default seccomp profile refuses it; admission
  control refuses SecurityOpt) and a local image build.
- Upstream SGLang has no disk Engram placement (only gpu|cpu; cpu needs ~189 GiB pinned RAM).
- The sybil-solutions adapter (PR #3 native AIO + PR #4 SM120 mask) reads Engram rows from disk
  with pread/native AIO on O_DIRECT. Both are allowed by the default seccomp profile. It needs
  only a start-time g++ compile, so it runs on the public, digest-pinned SGLang image.

## Problems found and fixed, in order
1. Traceback hidden: tqdm progress lines are joined by \r and the console log keeps 500 chars
   per line. Fix: TQDM_DISABLE=1, PYTHONUNBUFFERED=1, output piped through `tr '\r' '\n'`.
2. `unable to mmap 101535150936 bytes ... Cannot allocate memory`: shards 47/48 are 101.5 GB
   each (one Engram table + 4 small Engram tensors); a private mapping larger than RAM + swap
   fails on this host. The multi-thread loader also buffered whole shards (40 GiB limit hit).
   Fix: container-files/make_view.py builds /opt/model-view without the two tables (small
   tensors copied with pread into engram-small-N.safetensors), and
   enable_multithread_load=false. The adapter still reads the tables from /models/model.
3. Prompts > 64 tokens gave garbage (42 tokens correct, 74 wrong) although PR #4's mask is in
   flash_mla_sm120.py. Fix for now: SGLANG_SM120_FLASHMLA_BACKEND=triton (correct at 74, 178,
   185 and 29,198 prompt tokens; slower prefill). To do: find why the FlashInfer path still
   corrupts here.

## Measured (single stream, DSpark block 5, Triton FlashMLA, DSV41_CACHE_GIB=8)
- Decode: ~50 tok/s prose, ~99 tok/s code.
- Prefill: 29,198-token prompt in 11.6 s end to end (~2,500 tok/s); needle recalled.
- Load to ready: ~7 min. Memory: container 11-19 GB, host 17-24 GB of 63 GB, 0 OOM kills
  (memory-limit hits are page-cache reclaim while weights stream in).
