# 2026-07-08 -- Proposal: Eagle3 speculative decoding draft for Apertus 70B

**Goal:** Estimates for training a speculative-decoding draft head to speed up
decode (currently 30.7 tok/s single stream on the three-tier checkpoint).
Researched 2026-07-07 (web, primary sources); numbers recorded here so they
survive the chat.

## Why Eagle3 (SpecForge), not DSpark (DeepSpec)

| | Eagle3 / SpecForge | DSpark / DeepSpec |
|---|---|---|
| Apertus support effort | Mostly config (documented custom-target API; standard HF arch) | Weeks: only Qwen3/Gemma4 targets, hardcoded per-arch code, no registry |
| Data pipeline | Online mode, no offline cache | ~38 TB cache for their 4B recipe; extrapolates to ~120-240 TB for a 70B |
| Proven 70B recipe | Yes: lmsys Eagle3 for Llama-3.3-70B (1.4M open-perfectblend samples regenerated by target, 2 epochs, 8x H200, target served TP=4 via SGLang) | None beyond 14B + their own V4 |
| Serving | vLLM stable + SGLang | vLLM nightly only, custom kernels |
| Claimed edge | baseline | +16-31% accepted length over Eagle3 |

DSpark: ~2-4x the compute, a storage need that dwarfs it, first-mover risk.
Not worth it unless DeepSpec gains a target registry upstream.

## Eagle3 estimates (cloud; CANNOT train on this node)

- Data generation: ~1.4M samples x ~1k tokens = ~1.4B tokens through the
  70B target. On an 8x H100/H200 node with batched serving: ~60-130 h wall.
  (On this node at 30 tok/s: ~1.5 years -- hence cloud.)
- Draft training: SpecForge published 3.18 s/step at batch 16 for the
  Llama-3.3-70B recipe -> ~175k steps -> ~150 h on 8x H200 (~1,200 GPU-h)
  for the full recipe. Trimmed recipe (~500k samples): ~2 days.
- One-time engineering: register Apertus as a SpecForge target (standard HF
  arch -> mostly config; possibly a DistributedTargetModel impl for TP), a
  few days.
- Draft training VRAM: target dominates (TP across four 80+ GB GPUs for
  BF16, fewer with our FP8 checkpoint -- arguably better since the draft
  then learns the hidden-state distribution it serves against). Draft
  itself ~1B params -> ~16-20 GB with AdamW under ZeRO-2.

## Serving on this node (the payoff)

- NEW since the research: the vLLM Apertus implementation in our
  infomaniak image declares SupportsEagle/SupportsEagle3 (EagleModelMixin
  in apertus.py) -- serving a trained draft is already wired.
- Draft footprint: ~1B params ~= 2-3 GiB VRAM + small KV on top of the
  49 GiB target; costs ~10-15k fp8-KV tokens of headroom.
- Expected speedup: typically 2-2.5x decode -> ~60-75 tok/s single stream.
- Verify BEFORE training: vLLM eagle3 speculative config against a
  compressed-tensors mixed-precision target (nobody has published that
  combination).

## Prerequisite question

Train against the prerelease or wait for the final v1.5 release? A draft is
trained per-target -- retraining after the final release would double the
training compute. Recommendation: wait for the final v1.5 (or accept a
trimmed-recipe draft as throwaway), and meanwhile verify the eagle3 serving path with any
existing Eagle3 draft to de-risk the mixed-precision question.
