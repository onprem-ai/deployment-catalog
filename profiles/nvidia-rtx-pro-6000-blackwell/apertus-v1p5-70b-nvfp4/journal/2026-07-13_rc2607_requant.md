## What still needed curation

- **Chat template**: RC upstream still uses "+" string concatenation
  (TypeError on dict/int operands in the sandboxed environment -- the crash
  class this card hit three times) and still lacks dict-safe serialization of
  structured tool-parameter defaults. Re-merged: RC upstream base (which
  changes the reasoning delimiters from `<think>`/`</think>` to the model's
  own `<|inner_prefix|>`/`<|inner_suffix|>` specials and adds
  `waiting_for_tool_outputs`/`continue_assistant_message` handling) with all
  concatenation switched to "~" and the default-value tojson guard ported.
  All 6 scenarios in tests/unit/test_catalog_chat_templates.py pass.
- **config.json multimodal keys**: RC upstream config lacks the six omni keys
  (`vision_config`, `audio_config`, `dummy_{image,audio}_token{,_id}`) the
  apertus_mm serving path requires; ported from the previous checkpoint.
  RC's new `rope_scaling` (llama3-style, factor 8) + `rope_theta` kept.
- **Omnimodal encoder bundle**: `emu35_vison_tokenizer.safetensors` (1.7G) +
  `wavtokenizer_large_unify_600_24k.safetensors` (809M) must live in the
  model dir (apertus_utils asserts on them); hardlinked from the previous
  checkpoint.
- **Two-pass config.json surgery**: now automated --
  `fix_three_tier_quant_config.py` (this directory) rewrites the per-group
  targets and global ignore that llm-compressor 0.12.0 merges ambiguously,
  and fails loudly on unexpected structure. Result verified byte-identical
  (quantization_config) to the manually-surgered Prerelease reference.

## Post-deploy regression: "No generations found in stream" in the agent UI

Within the hour, an agent chat client failed on every message in threads
whose history contains a no-parameter tool call. Root cause: the RC-2607
upstream template (kept as the merge base) added a strictness check
`{%- if tool_call.name and tool_call.arguments -%}` and raises
"Invalid tool call" otherwise -- but empty arguments ({}) are legitimate
for no-parameter tools. vLLM 400s at safe_apply_chat_template, the
ai-gateway returns HTTP 200 with an empty SSE stream, and LangChain
surfaces "No generations found in stream". Fixed by rendering falsy/missing
arguments as {} (both the message-level and blocks-level tool_call paths);
regression test test_no_argument_tool_calls_in_assistant_history added.

Error-visibility follow-up (separate issue): the gateway converting an
upstream 400 into a 200-with-empty-stream hides the real error from the UI
and violates the surface-errors principle -- it should propagate upstream
error status/body.
