# 2026-04-25 — VRAM OOM: Model Too Large for 96 GiB

**Status:** UNSUPPORTED on RTX 6000 Blackwell (96 GiB VRAM)

## Problem

LTX-2.3 (22B) requires more VRAM than the RTX PRO 6000 Blackwell (95 GiB usable) can provide.

## VRAM Budget Breakdown

| Component | BF16 Size | FP8 Size |
|-----------|-----------|----------|
| Transformer (22B DiT) | ~43 GiB | ~22 GiB |
| Text encoder (Gemma 3 12B) | ~24 GiB | N/A (stays BF16) |
| VAE + audio + vocoder | ~2 GiB | ~2 GiB |
| Spatial upsampler | ~1 GiB | ~1 GiB |
| **Weights subtotal** | **~70 GiB** | **~49 GiB** |
| Inference activations/KV | ~10-20 GiB | ~10-20 GiB |
| **Total at inference** | **~80-90 GiB** | **~59-69 GiB** |

## What Was Tested

### Attempt 1: FP8 quantization (`QuantizationPolicy.fp8_cast()`), no offloading
- ltx-pipelines 1.1.2, PyTorch 2.11.0+cu128
- All components loaded to GPU
- FP8 stores weights in float8_e4m3fn, casts to BF16 for computation
- **Result:** `torch.OutOfMemoryError` — 94.24 GiB allocated, 94.93 GiB in use (of 94.97 GiB total)
- The FP8-to-BF16 upcast during attention (`fp8_cast.py:_upcast_and_round`) pushed over the edge
- Failed at the first transformer block's attention key projection

### Attempt 2: CPU offloading (`OffloadMode.CPU`), no FP8
- ltx-pipelines 1.1.2 (from GitHub main, adds `OffloadMode`)
- FP8 + CPU offload are mutually exclusive (`"quantization is not supported with layer streaming"`)
- CPU offloading loads the full model (~67 GiB) into system RAM, streams layers to GPU
- **Result:** The process was likely OOM-killed. Loading 67 GiB of model weights into system
  RAM on top of existing processes exhausted the host's free RAM.

### Why FP8 Alone Isn't Enough
The estimate of 45 GiB for FP8 was for weights only. During inference:
- FP8 cast quantization upcasts each layer to BF16 for computation (2x the layer size momentarily)
- The Gemma 3 text encoder stays in BF16 regardless (~24 GiB)
- Activations, attention KV cache, and intermediate tensors add 10-20 GiB
- Total exceeds 95 GiB

## Conclusion

LTX-2.3 (22B) is **not deployable on a single RTX 6000 Blackwell GPU** with current tooling.
The model was designed for 2x or 4x H100 setups (80 GiB each, with tensor parallelism).

## Potential Future Paths

1. **Quantized checkpoint (Q4/Q5)** — Would fit if Lightricks or community releases one
2. **Multi-GPU support** — Tensor parallelism across 2x GPUs (not available on RTX 6000 BW)
3. **Smaller variant** — If Lightricks releases a smaller LTX model (e.g., 7B)
4. **Better offloading** — If ltx-pipelines adds selective offloading (text encoder → CPU after encoding)
5. **Without spatial upsampler** — Might barely fit with FP8 if upsampler is skipped
